# IDS — 社群平台模擬前端

假訊息偵測系統的「使用者視角」前端。載入保留集（未餵進模型訓練的資料）並依真實貼文串顯示，與關係圖前端各自獨立運作，透過後端 WebSocket 聯動。

---

## 啟動

```bash
npm install
npm run dev      # http://localhost:5174
```

關係圖前端維持在 5173，兩者可以各自單獨啟動，互不影響。

後端網址預設 `ws://localhost:8000/ws/events`，要改的話在專案根目錄放一個 `.env`：

```
VITE_WS_URL=ws://localhost:8000/ws/events
```

**後端還沒好也能跑。** 連不上時右側導播台會顯示「後端未連線」，事件先暫存在本機佇列，後端一上線就自動補送，畫面操作完全不受影響。

## 版面

| 區域 | 說明 |
|---|---|
| 右上角 | 資料集下拉選單。未選擇時動態牆是空的；選了之後載入該事件完整的貼文與回覆串 |
| 左（主要） | 社群平台本體。刻意做成一個普通到不能再普通的動態牆 —— 使用者看不到任何風險標記 |
| 右（導播台） | 操作者的控制面板，深色儀器風格，視覺上刻意與平台異質。展示純使用者視角時可以收起 |

導播台兩個區塊：後端連線狀態、送出事件的即時日誌。**事件日誌是給教授看的證據** —— 選了資料集之後，裡面的傳播關係真的有送給後端。

## 資料集怎麼放進來

**資料集現在還沒有，這個資料夾是保留位置**，之後把訓練完成、確定保留集內容的資料放進 `public/datasets/`，前端不用改任何程式碼就能直接讀到。完整格式規格在 [`public/datasets/README.md`](public/datasets/README.md)，簡單講：

```
public/datasets/
├── manifest.json              ← 下拉選單清單，目前是空陣列 []
└── <資料集id>/
    └── thread.json            ← 這個資料集的貼文與回覆內容
```

`thread.json` 的欄位刻意對齊 `graph_analysis/builder.py` 既有的 `add_edge(source_user, reply_user, thread_id, is_rumour)` 邏輯，載入畫面的同時，也會把同一批傳播關係送給後端重新計算 centrality，不需要另外轉換格式。

## 設計說明

社群平台端故意走明亮、日常的方向，與關係圖前端的深色情報介面形成對比。這個對比就是 demo 的敘事：

> 使用者滑到的是一個乾淨、什麼都看不出來的介面；只有管理員那端才看得到底下的傳播結構。

因此**動態牆上沒有任何紅／藍風險標色**。風險判斷完全留給關係圖端，這是刻意的設計決定。

版面上唯一的重點是**轉發引用區塊左側那條細線** —— 它在使用者眼中只是普通的引用樣式，但它就是關係圖上的那條邊。

目前是**唯讀瀏覽器**：選資料集、看貼文串，沒有手動發文或身分切換功能。原因是資料集裡的帳號是真實資料集決定的，不是預先設定好的固定角色，手動扮演身分發文不再適用這個資料模式。如果之後需要保留手動操作功能（例如demo時想臨場加一則貼文），可以再另外討論怎麼設計。

## 事件格式

送給後端的事件欄位對齊 `graph_analysis/builder.py`：

```python
G.add_edge(source_user, reply_user, thread_id=..., is_rumour=...)
```

選擇資料集時，會把該資料集所有的回覆／轉發關係，逐一轉成 `share` 事件送出：

```jsonc
{ "type": "share", "id", "thread_id", "from", "to", "content", "is_rumour", "event_cluster_id", "ts" }
```

| 事件欄位 | 對應 builder.py |
|---|---|
| `from` | `source_user`（訊息從誰流出，即這則回覆的對象） |
| `to` | `reply_user`（訊息流向誰，即發出回覆的人） |
| `thread_id` | `thread_id` |
| `is_rumour` | `is_rumour` |

## AI 助手（右側浮動側邊欄）

畫面右上角有一個浮動的圓形按鈕，點下去會從右側滑出一個側邊欄，概念類似瀏覽器內建的 Copilot 側欄。這是專題後續延伸功能的前端雛型：**之後接上真正的偵測模型後，使用者可以框選畫面上的貼文，直接請模型判斷是謠言還是真實消息**。

**範疇說明**：這個功能目前運作在我們自己的網頁裡（框選、擷取這個頁面上的貼文），不是「像瀏覽器擴充功能一樣讀取任何網站」的等級——那種需要開發瀏覽器擴充套件（content script）才能做到，是另一個技術範疇，之後如果要做，需要另外規劃。

**框選怎麼運作**：點「框選貼文」後，拖曳滑鼠在畫面上框出範圍，放開滑鼠時會比對選取框跟每則貼文卡片的位置是否重疊，重疊的就整則擷取。這裡刻意不是做「螢幕截圖」，而是直接從資料裡取出貼文的完整內容——所以即使某則貼文很長、需要下拉捲動才能看完，擷取到的內容也一定是完整的一則，不會被螢幕當下顯示的範圍切掉。如果拖曳到畫面邊緣，會自動捲動頁面，不需要中斷拖曳動作。

**模型還沒好之前**：`src/lib/analysis.js` 裡的 `analyzePost()` 目前是佔位邏輯，每則擷取到的貼文都會顯示「模型尚未訓練完成」。等模型準備好，只需要把這個檔案內部換成真正呼叫後端推論 API 的程式碼，呼叫這個函式的其他元件完全不用改。

## 檔案結構

```
public/
  datasets/
    manifest.json               資料集清單（目前為空）
    README.md                   資料集格式規格
src/
  App.jsx                       主應用：資料集選擇、載入、AI 助手狀態管理
  main.jsx                      進入點
  styles.css                    全站樣式
  lib/
    backend.js                  事件格式定義 + WebSocket 連線
    datasets.js                 資料集載入器
    analysis.js                 AI 模型分析入口（目前是佔位邏輯，待模型就緒後替換）
  components/
    PostCard.jsx                貼文卡片（含轉發引用鏈、Avatar 頭像）
    ControlRail.jsx             導播台（連線狀態 + 事件日誌）
    AIAgentPanel.jsx            AI 助手側邊欄
    SelectionOverlay.jsx        框選擷取層（含自動捲動）
```
