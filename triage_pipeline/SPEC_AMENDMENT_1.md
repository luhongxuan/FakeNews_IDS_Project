# 規格增補 1（2026-11-27）：`time` 切分的邊界串與剖析順序
對象：`SPEC.md` v0.3（sha256 `4d922e28fa249b2844b5be2ff65b4e2422025271a9daefb12f1649f9ff2cb73c`）第 6.1、8、11 節。寫作時 `triage_pipeline` 尚無任何執行輸出。其他不變。

## 1. 邊界串：只丟「前一段」
**後一段完整保留，丟前一段中標籤尚未成熟的串。**
- 規則：令 `start(X)`＝區段 X 中最早的 `created_at`。前一段的串僅在 `created_at + H < start(後段)`（**嚴格小於**）時保留，否則丟棄。
- `start(X)` 取自分組後、該區段內**所有通過 schema 清理的串**（含零回覆串；在成熟度、候選母體與邊界丟棄**之前**），故不受 T、結果或過濾影響。
- 順序：先以 `start(測試)` 過濾選擇段，再以 `start(選擇)`（原定值）過濾訓練段。測試段不做邊界丟棄。
- 訓練段只對「緊接的」選擇段套用即可（`start(選擇) < start(測試)`）。
- 分組依 `(group_time, group_id)` 排序；一組不跨區段。丟棄是逐串的，整組被丟光則該組不算有效組。
- 分別計數：訓練段與選擇段因邊界丟棄的串數與整組丟光的組數。某段因此為空或有效組不足，照第 10 節回報 `insufficient_data`，**不得移動邊界或縮短 H**。
- 理由：模擬上線時，進入選擇期時只能用已完整的訓練標籤；測試資料不因 H 大小而改變。

## 2. 剖析使用的串（解決 H 與邊界互相依賴）
`time` 模式：
1. 依第 8 節的組比例定出原始訓練、選擇、測試區段（與 H 無關）。
2. 最長可觀察長度 `L = min(168 小時, 原始訓練段中已知 observed_until 之串的 min(observed_until − created_at))`；`observed_until` 全部未知時 L＝168 小時並標記。H 格點只取 ≤ L 者；沒有任何格點 ≤ L → `insufficient_data`。
3. **剖析集合**＝原始訓練段中 `created_at + L < start(選擇)` 且（`observed_until` 已知時）`observed_until ≥ created_at + L` 的串。H、T 都只用剖析集合。剖析集合為空 → `insufficient_data`。
4. H 決定後，才依第 1 節以該 H 產生用於擬合的訓練段。訓練段因 H < L 可能比剖析集合大，這是預期行為。
- `H` 準則的分子分母：剖析集合所有串的回覆，偏移 ≤ H 的總數 ÷ 偏移 ≤ L 的總數（依共用清理規則，只按時間，含他人回覆）。分母為 0 → `insufficient_data`。
- T 準則的分子分母：同一剖析集合，在所選 H 下；候選串（T 時他人回覆 ≥ `min_replies`）在 (T, H] 的他人回覆總和 ÷ 全部剖析串在 (0, H] 的他人回覆總和。（分母固定，不隨 T 改變。）

`leave_group_out` 模式：無時間邊界、不丟邊界串；剖析集合＝該外層折其餘組中滿足成熟度（`observed_until` 已知時）的全部串；L 依同一公式對這些串計算。

## 3. 學習曲線（第 11 節）
使用第 1 節處理後的訓練段，取最接近選擇段的 N 個**仍有串的**組。H、T 不因 N 改變。

## 4. 必須新增的測試
邊界恰為 `created_at + H == start(後段)` 者丟棄；零回覆串參與決定 `start`；改變 H 不改變測試段成員與各段 `start`；整組丟光的計數；剖析集合不含任何 `created_at + L ≥ start(選擇)` 的串；竄改非剖析集合的回覆不改變 H、T。
